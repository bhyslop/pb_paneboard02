# JJK Bridling — Designating a Pace

Read this before you bridle, whenever bridling or warrants are under discussion.
It is an **excursus** (`jjsuc_excursus`): held out of the standing session load
and read on demand, reached from the trigger line in
`Tools/jjk/volis_jjk.md` "Bridle Protocol". Never bridle from memory of
this file — the tier you rule and the criteria you write are both licences you
are granting, and a half-remembered licence is the failure this door exists to
prevent.

What stays resident in the conduct home is deliberately short: the vocabulary,
and the three dispositions that bind apart from this read — that rough is the
absence of a ruling rather than a signal standing in for one, that a redocket,
transfer, or relocate silently voids a designation, and that a lope is refused
a bridle outright. The judgment itself is here, all of it.

The law this file serves is homed in Job Jockey's specification
(`specs/jjk/JJS0-JobJockeySpec.adoc`: the warrant sections, and the
*Criterion Authorship* principle that governs how a criterion is spelled),
cited here as depth. Every rule from it that a criterion's author must obey is
restated below; this file is the craft of obeying them.

## Who you are when you read this

Assume a fresh chat. A pace is slated by one session and bridled by another,
days later, and the two share nothing but the durable record: the docket, the
paddock, the landed specs, and whatever you go and read. That is the ordinary
reader of this file, not a degraded one, and the steps below are written for
it — so where a step names what *this session holds*, a fresh chat holds
nothing, and the equivalent input is what it can go and read.

What that reader owes is the going. Both judgments below rest on facts as they
stand now rather than as the docket recorded them, and no docket reports its
own staleness. A bridler that slated the pace in this same chat may skip a read
it has genuinely already made; it may not skip the standard.

## The designation procedure

1. Read the candidate pace whole with ONE `jjx_show` aimed at its coronet. The
   docket and the heat's paddock ride the gazette, and the sire block rides the
   inline result — so the three readings this procedure needs arrive together.
   Both the docket and the paddock, never the docket alone: you cannot know
   whether heat context bears on the judgment until you have read it, so a
   conditional here would only ever be answerable by a reader who did not need
   it. (`jjx_brief` and `jjx_paddock` still answer their own questions; what
   they no longer are is the way to open a designation.)
2. Prove the docket's work against the **trees a dispatch would stand up**, from
   the sire block that read just gave you. Name the trees the work reads and
   writes, and answer each against what the block reports: the **write sire**,
   the **declared read list**, and **what registration adds**. A tree the work
   needs and none of the three provides is a refusal to designate — and the
   remedy is the read-list edit (`jjx_whorl {coronet, readable_sires}`), which
   must land BEFORE the bridle, because that field voids a designation.
   This step exists because the failure it catches is invisible at execution
   time in the worst way: a designee handed a docket that reads a tree its kraal
   was never given does not meet a refusal, it meets an absence, and an absence
   is what an agent improvises around.
3. Judge **readiness**: does the docket have gaps — an ambiguity, a missing
   decision, a question only the operator can answer, a named site that has
   moved out from under it? If so, REFUSE to designate and report the gaps —
   a gap is a reslate need. **Refuse only for gaps.** "This pace needs judgment
   to execute" is NOT a gap and is NOT a reason to withhold designation; it is
   the finding that sets the tier to a frontier one. Refusing to bridle a
   ready pace because its work is hard is the failure mode this step exists
   to prevent.
   One item in the list above is not always a gap: before you call "a question
   only the operator can answer" a reslate need, run the lope test below.
   Three gap classes carry it. The first two show in the docket's text shape;
   the third does not, and is the one a reader that only reads will pass every
   time.
   - **Scope-legibility gap.** A docket that quantifies over a set of code
     sites ("every mutating command", "all X") is ready only if it carries
     the set's heterogeneity census — the enumeration plus the per-member
     facts that shape the work — or mandates that census as the mount's
     first checkpointed artifact. Absent both, the forks that shape the work
     are invisible: name the census as the reslate need.
   - **Affordance gap.** A done-when promising per-member proof ("tests
     land each X") is ready only if the harness affords driving a member
     end-to-end. If it does not, the docket must either scope the
     affordance in or name the accepted lower bar — an operator decision
     at slate, never an executor's reinterpretation at land.
   - **Staleness gap.** The other two are properties of the docket's text;
     this one is a property of what the text points at, so a docket that
     reads perfectly can carry it — a named entry point now absent, a
     discovery recipe that no longer reaches what it names, a cited section
     that has moved. It is not discharged by reading: go resolve the sites
     the docket names, because a docket whose named sites have moved is a
     reslate need, not a discovery for the executor to absorb.
   Staleness is the one this gate is worst placed to catch, because it is the
   only one a careful reading cannot find: it is what the going above is for.
   At a full-ceremony mount of a rough pace a gap is a stop-and-surface; at
   this gate it is a refusal to designate.
4. Judge the **tier**: where does judgment live *during execution*, not how
   much the pace matters. Operator presence LOWERS the requirement (judgment on
   tap, so the designee just executes carefully and surfaces clearly), and
   stakes hold no tier since stop-and-surface already forbids improvisation.
   What holds a frontier tier is plausible wrongness the operator cannot
   cheaply check — work that authors authority downstream work will obey (a
   ceremony document, a spec narrative), where an error reads fine and
   propagates.
   Structural work bears the same signature: a pace that moves, renames, or
   excludes within a system carrying enrollment registries, shared constants,
   or generated artifacts is never merely mechanical — its errors exit zero
   and surface only downstream.
   Fresh authorship under the discipline-guide corpus bears the multi-pass
   signature: guide-violating residue reads fine to its author and surfaces
   only at frontier review. Verbatim seating, transplants, and settled-recipe
   edits forecast one-pass; fresh authorship under RCG/BCG does not.
   The tier ruling carries a second forecast: how the wrap review converges.
   A sub-frontier tier discounts the worker leg alone — every repair cycle
   buys a fresh frontier review of the whole billet plus the designee's
   repair turns, and a single cycle typically consumes the discount on a
   small-to-mid pace. Designate sub-frontier only where a one-pass review
   land is the honest forecast.
5. Before settling on a frontier tier, weigh mechanization: if the judgment
   the docket defers could be settled NOW — from the paddock's cinches, the
   landed specs, and what this session either holds or can go and read —
   propose the reslate that bakes those decisions in, leaving a residue a
   lower tier can run (the proposal goes to the operator; on approval,
   redocket, then bridle). Judgment only the work itself can surface — spec
   authoring, gates, verification — is not mechanizable: designate it at its
   frontier tier rather than manufacture a reslate, and never leave it rough
   as a substitute for designating it.
6. **Drive the door, or read its code, before you author any criterion over
   its output** — and record in the warrant which of the two you took and what
   it showed. Every instrument a criterion will read from is an artifact with a
   standing shape: a build door, a suite, a reading door, a gate whose refusal
   you expect. The shape you carry in your head is a *description* of
   that artifact rather than the thing, and one drive — or one reading of the
   code that emits it — settles what the description cannot: the field names,
   the exit convention, whether the reading can move at all, and whether the
   property you mean to assert is one this instrument reports.
   The **record** is what makes the step bite. Nothing parses it and no door
   enforces it; its whole force is that a warrant carrying no such line makes
   the skip a **visible absence** rather than a silent omission, so a later
   reader of a red criterion can part an artifact that moved from an author who
   never looked. Say it either way — a warrant whose criteria read no tool
   output says *that* in a line.
   **The record is per criterion, not a paragraph of its own.** Each criterion
   names, in its own line, the drive or the read that produced its expected
   side — driven at this bridling, read off the emitting code, or taken from a
   standing reading and dated. A paragraph can be true of the warrant and false
   of its fifth criterion, and it goes on reading true as criteria are added
   under it; a clause on every line cannot, because a side that was modeled
   shows as a **visible blank in a column of filled ones** rather than as a
   silence inside prose asserting the warrant looked at something. The worked
   warrant at the foot of this file carries the form on every one of its
   criteria.
   This step exists because the failure it catches is invisible without it: a
   modeled criterion is spelled exactly like a driven one, wearing the costume
   of diligence, and it fails cheap by redding correct work and expensive by
   reading green over a verification nobody performed. The recurrence is
   recorded rather than argued —
   `memos/memo-20260831-warrant-authoring-watch.md`, whose specimens are the
   evidence that reading a door's description is not driving it.
7. **Write the warrant.** Every bridle carries one, so this is not a grade to
   weigh but a step to complete: the criteria must be executable — commands
   with expected outcomes, never judgments to weigh. Writing them IS the
   eligibility test, and it is what turns the repair-cycle forecast in step 4
   from a bet into a check. Criteria that will not come out executable at a
   sub-frontier tier are a finding, not a downgrade: either the docket needs a
   reslate or the work needs a frontier tier, and the litmus below parts them.
   The authoring discipline and the wire format are the rest of this file.
8. Designate: `jjx_apostille {coronet, tier}` with the execution tier
   (haiku | sonnet | opus | fable), adding `effort` (low | medium | high |
   xhigh | max) only where the docket's depth is judged. At a sub-frontier
   tier, an effort word above low is evidence against the tier ruling
   itself: depth the bridler can already see is depth the wrap review will
   re-walk, one repair cycle per finding. Only a rough pace with no kind may be
   bridled — a lope IS rough, so it is refused on the kind rather than on the
   state, under its own sentence naming the kind and the flip back.
   Stage the `jjezs_warrant` notice immediately before this call — the door
   refuses a designation with none.

## The lope test: when the question IS the pace

A **lope** is a pace carrying the hackamore kind — work that completes in
conversation with the operator rather than by execution. The kind is a durable
axis of its own beside the bridle designation, never a tier, and it is the one
finding at step 3 that looks exactly like a gap and is not one.

The two read alike on the page and part on what a repair would cost:

- A **gap** is a docket that could have been written whole and was not. One
  decision is missing from work that is otherwise executable, and a reslate
  fills it in. If you can imagine the sentence that closes the question, this
  is a gap.
- A **lope** is a docket whose work *is* the conversation. The question is not
  a hole in the specification — it is the thing the pace exists to settle, and
  no reslate can answer it, because answering it would be doing the pace. If
  closing the question would take the conversation the pace was slated for,
  this is a lope.

Report a lope as a lope. Name the kind, and name the flip —
`jjx_whorl {coronet: "<coronet>", kind: "hackamore"}` — as the remedy. Do not
demand a reslate: a docket forced into executable shape to satisfy this gate
throws the work away, and the pace that comes back is a different pace. Do not
designate either; a lope carries no tier, and `jjx_apostille` refuses one
outright, naming the kind and this same flip. The flip is the operator's to
make — recommend it and stop, exactly as you stop on any refusal here.

The mirror binds too. A pace already standing as a lope is not a candidate, and
note *why*: it is rough, so nothing about its state puts it out of scope — the
kind does, and you must read the kind to see it. `jjx_coronets` tags it
`[hackamore]`, and the rough filter drops it for this reason. A lope that has
settled — its thinking banked, its docket redocketed into executable form, its
kind flipped off — arrives here as an ordinary rough pace with no memory of
having been one, which is the point.

**None of that reaches the other kind.** A pace carrying `poort` — work that
runs solo against shared durable state — *is* a candidate, and everything above
is about hackamore alone. `jjx_apostille` refuses it nothing, the rough filter
keeps it, and `jjx_coronets` tags it in its own bracket group *after* the state
rather than in place of it (`[indult opus]  [poort]`), because that kind adds a
fact where hackamore corrects one. Bridle it on the docket's merits and leave
the kind where it stands: exclusive-and-indult-at-opus is the ordinary shape
for schema work, and the kind's gate — the operator's word at the mount that no
other chat is working — is a different question from what tier the execution
needs. Never flip a kind away to make a pace designable; that discards the
slater's statement of what the work is to satisfy a gate it was never subject
to.

## What a warrant is

A **warrant** is a frontier-authored briefing attached to a bridle, and **every
bridle carries one** — `jjx_apostille` refuses a designation with none staged.
It tells the designee what to do, and its criteria say what would prove the
work done.

## The eligibility litmus: writing it IS the test

There is no separate rubric for "is this pace ready for a designee". **Try to
write the criteria. If you cannot make them mechanical, the pace is not ready
for a designee** — and that finding is a real one rather than a downgrade. It
is honest because it costs you the same work either way.

Two outcomes follow, and neither is a designation made anyway:

- **The docket is the problem** — the criteria cannot be written because the
  work is not specified sharply enough to say what done looks like. That is a
  reslate need. Surface it and stop.
- **The work is the problem** — the criteria cannot be written because the work
  genuinely needs judgment throughout. **Bridle it at a frontier tier**, with a
  warrant whose criteria are the ones a frontier session can still drive (the
  build, the suite, the gates). That is a first-class designation, not a
  consolation prize — see the rough-is-not-a-signal disposition in the conduct
  home.

A criterion is mechanical when it is *a thing to run and an outcome to compare
against*. It is not mechanical when it asks the designee to weigh, judge, or
decide whether something is good.

```
✅ Run tt/vow-t.Test.sh — exits 0, and the count is at or above the 938 it
   stood at when this warrant was written.
✅ git -C <tree> grep -n 'jjy_' -- Tools/jjk/volis_jjk.md — zero hits.
✅ tt/vow-b.Build.sh — exits 0.
✅ The file Tools/buk/buym_yelp.sh contains no line matching '^\s*local -r' .

❌ The refactor reads cleanly.            (weighable)
❌ The naming follows RCG.                (weighable — and if you can name the
                                           specific violation, make THAT the
                                           criterion)
❌ Nothing else broke.                    (unbounded; the suite is the criterion)
```

If a docket's real work is spec narrative, a design ruling, a ceremony
document, or anything whose error "reads fine and propagates" — that is
frontier work. Bridle it at a frontier tier. Do not manufacture criteria for
it.

**Mechanical is not the same as true.** Verify each criterion against the
governing text and the standing output of what it reads — the file opened, the
door driven once, the rule's own words — never against your remembered or
modeled picture of that artifact: the mechanical form makes a comparison
runnable and does nothing to make its expected side right. A criterion whose
expected side was modeled is a criterion about an artifact that does not
exist, and it fails cheap by redding correct work and expensive by reading
green where the modeled shape happens to admit the standing one. The specimen
is a criterion that modeled a tool's capture as narration plus a table and
never modeled its findings stream, whose particulars carry file paths as
data — it redded correct work and was overruled at the wrap.

Five spellings follow from that rule, and each is law rather than counsel. The
recurrences that earned them are recorded in
`memos/memo-20260831-warrant-authoring-watch.md` and are deliberately not
retold here — a wording that has to carry its own specimen to bind has not
become law yet.

- **A criterion naming a tool's output names the FIELD it will be read from,
  never the token alone.** A token that can turn up as incidental noise in a
  report is not a criterion, whatever it is a criterion about: read loosely it
  is graded met by a reader who verified nothing, and read literally it is
  graded red against work that is sound.
- **Counts are relative to the diff and proven at the base.** Every
  criterion over a gate's findings takes the relative form — no finding *this
  diff* introduced, the same reading taken at the fork point as its proof — and
  never an absolute. An absolute grades the pace against debt it inherited, so
  a sharpening that lands mid-batch reds correct work and costs an operator
  waiver. The same holds of any threshold a suite total or a site count moves.
- **Criteria grade seats rather than occurrences.** Prose legitimately names a
  token — a declaration, a note recording why something is deliberately not an
  input — so a criterion counting hits grades the tree's incidental mentions
  alongside the thing it meant to judge.
- **Criteria assume no station.** Station-local arithmetic — a core-count
  probe, a utility this repository does not declare, a path one machine alone
  carries — is met by a designee running somewhere else, and a warrant never
  says where its designee will stand.
- **A criterion ordering a build names which door proves which crate.** A green
  build verdict proves the crate its own door builds and nothing beside it, so
  a build named loosely stands broken callers behind green.

Two further spellings bind the *trees* a criterion may name, and the first of
them is now refused at the designation door rather than left to your care: a
warrant naming a kraal directory in any shape the yard has ever minted is turned
away, the token named back to you.

- **A criterion names the mounting kraal's own trees, never a sibling kraal's.**
  A kraal is swept when its pace resolves, so a criterion pinned to a
  neighbouring one names a tree its designee never stands beside — and it grades
  correct work red for as long as the warrant stands, because nothing in the
  criterion's own text says which yard it belongs to. Spell a door
  seat-relative, or leave a placeholder its executor fills for the seat it
  holds; an identity names the work without naming a directory at all.
- **A docket premise resting on an unconverged branch says so.** Corpus work
  stands in its own pace's vulgate billet until that pace wraps, so a premise
  citing it as trunk-resident sends its reader to a tree that does not carry it
  yet. Name the branch the premise stands on, and the reader knows what it holds
  rather than concluding the work was lost.
- **A criterion naming a fork point says which axis's fork it means.** A kraal
  stands two billets and they fork from different trunks: the work billet's fork
  is the merge base against the work trunk's remote counterpart, and the vulgate
  billet's is the merge base against the *corpus* counterpart, never the work
  trunk. The two are unrelated histories, so a criterion that says "at the fork"
  and leaves the axis to its reader sends a corpus-authoring designee to a base
  its own billet cannot answer — the reading refuses, or resolves against a tree
  that carries none of the work being graded. Spell which counterpart the fork is
  taken against in the criterion's own text, the way the tree beside it is
  already spelled as a placeholder its executor fills.

**A criterion is text another session runs from a seat you cannot know**, and
that constrains how it may be spelled. Three rules follow, each binding the text
rather than the run. Their home is JJS0's *Criterion Authorship* principle,
cited as depth; what a criterion's author must obey is all here.

- **A criterion names no root spelling that presumes a working directory.**
  Where a root must be spoken of at all it is named as a *tree* — the
  repository, the corpus — and the executor spells it for the seat it actually
  stands in. A rooted path pins its reader to one clone, and a billet-relative
  path pins it to one pace, the billet's name carrying a serial and a coronet.
- **An exclusion glob in a criterion is anchored so that it matches at any
  depth.** A glob is tested against each path as the walk constructs it,
  prefixed by the root actually passed, so one written relative to the
  repository root stops matching the moment that root is spelled as anything
  but a bare `.` — which is every spelling open to a session that cannot move
  its seat. The failure is silent and inverted: the excluded sites surface as
  hits, the criterion reds a run that passed, and its executor is invited to
  repair matches that are not defects or to loosen the pattern until it goes
  green.
- **Where a check has a door that resolves its own tree, the criterion cites
  that door rather than hand-rolling the search.** A repository's own search is
  such a door: handed the tree, it resolves the repository root itself and
  reads the criterion's path arguments against that root, so the class above
  cannot arise. A search utility the repository neither declares nor requires
  fails at a station lacking it as a work defect rather than as an absence.

These rules govern durable text and never live invocation, and the two do not
overlap. A session never moves its own seat, and reaches another tree by a path
resolved from that seat; a criterion names the tree and no root at all, its
author not knowing where it will run. The discriminator is the text's own tense:
a path typed into a command this session runs now is spelled from the seat, and
a path written into text another session will run later names no root.

The idiom that follows is the repository search — `git -C <tree> grep`, never a
bare `grep -r` against a named directory and never a station utility this
repository does not declare. `<tree>` stays a placeholder, the executor spelling
it for its own seat, git resolving the repository root from it and reading the
path arguments against that root. Where the outspan you stand in also carries
`volie_custumal.md`, this estate keeps a census tool whose doors answer name
questions a search cannot grade, and that door says when a criterion cites one
instead; where it does not stand, the search is the whole idiom.

Three rules bind a **zero-hit** search, each about what the search actually
sweeps rather than what it looks for. **A zero-hit grep names the file it
sweeps, never the directory a test the same warrant orders will land in** — the
two orders are each right alone and contradictory together, and the
contradiction is invisible on the page because the seat the test takes is
nowhere in the grep's own text. **A zero-hit grep over prose names a phrase
short enough to stand on one line, or reads the file with its lines folded** —
prose is authored to semantic line breaks, so a phrase spanning a wrap is
absent from every line while standing whole in the file, and the criterion
reads green against a tree that carries the sentence. And **a zero-hit grep
spells its word boundary with `-w`, never `\b`** — `\b` under `git grep -E` is
inert on some stations, so `name\b` matches nothing and the criterion reads
green against a tree that carries the name.

## Authoring discipline

**Write to a colleague, not to a machine.** The register is one model briefing
another with what it needs and what will bite it — the prior art
(`memo-20260224-jjk-v4-gaits.md`, "Warrant: Model-to-Model
Communication") calls it exactly that, and it still holds.

What earns its place in the body:

- **The entry points.** Which files, which functions. Not a tour of the module.
- **The pattern to follow.** Point at the existing site that already does it
  right; the designee copies a real precedent better than it invents from prose.
- **The hazards.** The shared constant both files need. The generated artifact
  that must be re-rendered. The thing mid-refactor in another heat that must not
  be touched.
- **The criteria**, last, under their own heading, one per line, each with its
  expected outcome.

What does not belong: restating the docket (the designee reads both, and the
docket stays the authority for *what this pace is for*), architectural
commentary, or reassurance.

**The warrant is the sanctioned home for prescription.** The over-15-lines
suspicion that governs dockets does not govern warrants — that split is
deliberate, and it is what stops designee-prep from bloating dockets that
judging readers have to wade through. Be as concrete here as the work requires.

## Name the reach before you grant

Before you write a line, answer for yourself: **what should this pace touch?**
Name the files. If you cannot — if the honest answer is "depends what it finds"
— the pace is not mechanical, and that is your eligibility finding: take it to
the litmus above and part the two outcomes there.

This is a thinking prompt, not a gate. Nothing checks the answer, and nothing
should: a declared file list is a prediction, and the same estate doctrine that
bars site enumerations from dockets applies to predictions made at bridle time.
Its value is upstream of the warrant — a pace whose reach you can state in a
breath is a pace whose criteria will come out executable, and one whose reach
you cannot state is telling you something before you have spent an hour on it.

Then write the reach into the warrant **as prose**, where it belongs: "the three
call sites are in `Tools/buk/buym_yelp.sh`", "do not touch the capture path".
The designee reads that and honors it: off-warrant discovery **halts** the pace,
it never wraps it.

## Ordering a door drive: name the seat

A criterion that says **drive the door** — run the dispatch, the wrap, the notch
for real rather than reasoning about it — is a good criterion, and it is the one
kind that can do damage from the warrant alone. A door resolves whatever store
its launch stand's infield names, so a drive that is told to run and not told
*where* resolves the **production studbook** by default. That is not a mistake a
careful designee avoids; it is the default, and it destroys every concurrently
active session in the estate when it fires.

The law is `JJr_t3w` in the studbook sheaf, and its W4 clause binds **you**, at
this moment, rather than the designee: a warrant that says drive the door owes
the drive its seat, named explicitly. Silence is not neutrality.

**The seat is the quintain** — `jjtdq_quintain`, in the equerry's veiled test
tree. It composes, under a reaped temp root, the whole yard a dispatch resolves:
a launch stand, the sires, and a studbook clone seeded with the committed
synthetic replica and tracking a scratch bare of its own. The drive reaches it
through the equerry's **unchanged** resolver — the walk from launch stand to
infield to studbook is a join, never a search — so nothing about the door under
test is special-cased to make the proof possible. Its own gate refuses to spawn
a drive whose yard would resolve outside that temp root, and refuses one whose
clone would push outside it even when every path reads clean.

So a door-drive criterion names it, in a line:

```
- The dispatch drive runs green against the quintain (jjtdq_quintain), its
  record observed in the scratch journal — never the production studbook.
```

**A drive ordered under a door law is ordered with its notch first, and the
warrant names the law.** Estates and kits carry standing rules about the state a
tree must be in before a door runs — a door that refuses a dirty tree, which
the kennel's doors do at the build as much as at the suite, or a preference
that every build, suite and fixture drive be notched first so each result maps
to a committed position. An author who holds the law writes the notch into
the criterion; one who does not orders the drive alone, and its designee meets a
refusal it has to diagnose mid-pace or, worse, a green reading it cannot tie to
any commit. Say notch first, and name the law you are ordering it under, so a
designee standing under a different one can tell what it owes.

Two things you are **not** granting when you write that. You are not licensing
an equerry edit: the fixture exists precisely so the resolver stays untouched, so
a designee that reports needing an equerry change to make a drive contained has
found a hole and **halts**. And you are not licensing a drive anywhere else — a
criterion that names no seat is the one this section exists to stop you writing,
whatever else the warrant gets right.

## Ordering a falsification: arm the gate first

Arm a gate before you order it falsified — above all where the driven door
**spends the pace**, since nothing comes after it to catch the omission. What
stands here is why the rule bites and the specimen that earned it.

This is the sibling of the section above, one step further in: that one governs
where a drive lands, this one governs whether the gate the drive was aimed at
ever engaged.

A criterion whose expected outcome is a **refusal** proves nothing until the
refusing gate has actually run. A gate that passes because what it judges is
absent has returned the *absence* of a refusal rather than its negation, and a
criterion that reads that absence as evidence closes a verification nobody
performed. The positive control the resident rule calls for is the same drive
over the same armed state without the fault, proving the gate reaches a verdict
at all.

Two rules bind the control itself, and both are about what the control is able
to detect rather than what it asserts. **A positive control for a tree-reading
door is a token standing in the diff alone — one the pace itself introduced —
so a wrong-tree read fails the control.** A token standing identically in the
billet and in the tree the door might wrongly read is struck either way, which
is exactly the condition the control was armed to catch, and the criterion
cannot then be met as written. Its mirror: **an absent-everywhere control must
be absent from every tree the door may read.** A kit copied into a second sire
carries its tokens there too, so a token chosen as absent against one tree is
present in the reading the door actually takes.

The specimen is a warrant that ordered its falsifying wrap attempts ahead of
any committed corpus delta, where the wrap gate by deliberate design passes
without consulting the corrector roster when nothing would land — the expected
refusal came back a pass, and the pace closed over a verification never
performed.

## Wire format

One **lede-less** notice staged in `gazette_in.md` immediately before the call:

```
# jjezs_warrant
The equerry work is in vov_veiled/jjk/src/jjr0/jjrz_gazette.rs …

## Criteria
- tt/vow-b.Build.sh exits 0
- tt/vow-t.Test.sh exits 0 with no fewer tests than before
```

The header is `# jjezs_warrant` **alone**, and a lede is refused rather than
ignored: the `coronet` param on the call is the sole address, so a second copy
of it in the notice could only ever agree or disagree. This is the one-address
ruling — the notice is payload, the param is the address. (`jjx_rodear`'s notice
is lede-less too, but for the opposite reason: the cavvy has no identity to name
at all, where a warrant has exactly one and it already rides the call.)

Then `jjx_apostille {coronet, tier, effort?}`.

Rules the door enforces, so you meet them deliberately rather than by refusal:

- Exactly one notice, non-empty body, **no lede**.
- The notice is **required** on any designation — a call with nothing staged is
  refused, there being no unwarranted grade to fall into.
- Staged input on a `release` is refused — a release wipes the warrant, so a
  staged notice there means you meant the other call.
- Only a **rough** pace may be bridled. To rewrite a warrant on a standing
  bridle: `jjx_apostille {coronet, release: true}`, then bridle again.
- Remember the gazette's one-call lifetime: any refusal consumes the staged
  notice, so re-write it before you retry.

## What voids a warrant

A designation is void when its judgment inputs change, and the warrant goes
with it — wiped alongside the tier by **any redocket** (single or mass
reslate), a **sire** or **kind** edit through `jjx_whorl`, **transfer**,
**relocate**, or deliberate **release**. Silks, predecessors, and reorder void
nothing — so a `jjx_hopple` or `jjx_unhopple` against an indult pace leaves the
warrant standing, and scheduling work never has to wait on a designation. Tier, effort, and warrant all persist through close as
provenance of the executing session — the warrant especially, since the forensic
trail it exists for is only readable after the fact.

**A refit voids driven criteria, not the warrant.** The designation stands and
the designee keeps its licence; what it loses is the *evidence*, gathered on a
tree the merge has moved, so it re-drives each criterion before closing. Since
refit is now open to every tier, a designee can clear its own staleness — and so
can invalidate its own green mid-pace. Nothing enforces the re-drive, so **write
criteria a session can cheaply re-run**: one whose evidence took an afternoon to
gather is one a designee will be tempted to carry across a refit instead.

**A count criterion says what a sibling landing cannot move.** A number read at
the mount and compared at the close is an equality only while this billet is the
sole author of the tree it reads, and in a parallel field it usually is not — a
sibling pace landing inside the window is what the refit above is the sign of.
The close reading then carries that sibling's motion as well as this pace's, and
the criterion reds correct work for a delta it never authored. So state a
close-versus-mount count against the merged tree with the sibling landings netted
out, or drop the count for a per-site proof — the seats this diff touched, named
— and never as a bare equality a refit can void.

## A worked warrant

```
# jjezs_warrant
The three call sites are in Tools/buk/buym_yelp.sh — search for `buym_yawp`.
Each one builds its format string inline; the goal is that they all route
through the resolver that already exists at the top of the file
(`zbuym_resolve_format`), the way `buym_yawp_diastema` already does. Copy that
call shape exactly; it handles the empty-format case, which the inline builders
do not.

Two things will bite you. `BUYM_FORMAT_LEGACY` is read by both this file and
Tools/buk/tests/bujy_yelp.rs — leave the constant where it is, only change who calls
it. And the third site is inside a subshell, so a bare `return` there does not
do what the other two do; that one needs the `|| exit` form the resolver's own
callers use.

Do not touch the capture path (`buym_capture_*`). It is mid-refactor in another
heat.

## Criteria
- tt/bkw-m.Mush.sh bun_suite exits 0 — driven at this bridling, exit and
  colophon read off the run
- git -C <tree> grep -n -w 'zbuym_resolve_format' -- Tools/buk/ returns 4
  lines, all in Tools/buk/buym_yelp.sh (the definition plus three callers) —
  driven at this bridling; the 4 is the standing reading, not a forecast of the
  edit
- git -C <tree> grep -n 'printf.*%s.*%s'
  -- Tools/buk/buym_yelp.sh returns zero hits — the three current hits were read
  at this bridling and are exactly the three call sites the body names
- tt/vow-t.Test.sh exits 0 — exit convention read off the door, not driven; the
  suite is ordered here as a regression guard and no total is asserted
```

Note what it does *not* do: it never says "make the code cleaner", it names the
one precedent to copy, it spends most of its length on the two hazards, states
the reach in prose rather than as a list, and gives every criterion a command,
an outcome, and the clause saying where its expected side came from.
